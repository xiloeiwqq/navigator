# Навигатор кампуса — прототип

Первая версия веб-навигатора по учебному корпусу, собранная по описанию экспоната «Навигатор студента».

## Что уже работает

- поиск текущей или следующей пары по группе и времени;
- кратчайший маршрут по графу помещений;
- переключение схем трёх этажей;
- пошаговые подсказки, расстояние и примерное время пути;
- маршрут без лестниц;
- перестроение при закрытии отдельного прохода;
- адаптивный интерфейс с приоритетом телефона;
- автоматическое открытие мобильного QR-сканера при входе без QR-параметра;
- распознавание QR в живом видео или на снимке без отправки изображения на сервер;
- применение `start_node`/`node_id` из QR и мгновенное перестроение маршрута;
- явный выбор между быстрым маршрутом по лестнице и безбарьерным путём через лифт;
- автоматический выбор между тестовым и реальным расписанием без изменения кода;
- актуализация CSV-расписания без перезапуска сервера и без браузерного кеша;
- диагностика сервера через `/api/health`.

В проекте используются демонстрационные схема и расписание на **16 ноября 2026 года**. Для каждой тестовой группы добавлено по пять разных 90-минутных пар до 17:00. Группы по очереди занимаются в аудиториях А-101, А-201 и А-301 на трёх этажах и не пересекаются в одном кабинете; повторные нажатия «К следующей паре» последовательно переключают занятия. Эти данные нужны только для проверки функционала и не описывают реальное здание.

## Запуск

Нужен Python 3.11 или новее. В папке проекта выполните:

```powershell
python app.py --check
python smoke.py
python app.py --host 0.0.0.0 --port 8080
```

Затем откройте:

```text
http://127.0.0.1:8080/?start_node=entrance
```

Node.js нужен только для запуска JavaScript-тестов через `smoke.py`.

Если Python не установлен, тот же прототип можно запустить сервером без зависимостей на Node.js 18+:

```powershell
node test_route.js
node server.js --host 0.0.0.0 --port 8080
```

На компьютере страница доступна по `http://127.0.0.1:8080/`. Телефон в той же Wi-Fi сети открывает LAN-адрес компьютера, например `http://192.168.10.254:8080/`.

> Браузеры разрешают непрерывный видеопоток камеры только в безопасном контексте: HTTPS или localhost. Поэтому на обычном LAN-адресе по HTTP сканер автоматически предложит кнопку «Открыть системную камеру»: снимок будет распознан локально. Для живого сканирования на телефоне публикацию нужно перевести на HTTPS.

## Демонстрационные сценарии

1. **Следующая пара:** открыть `/?start_node=entrance`, выбрать группу `ИСП-21` и время `16.11.2026 09:45` → аудитория А-201, маршрут 25 м. Повторное нажатие «К следующей паре» переведёт маршрут в А-301 на третьем этаже.
2. **Между этажами:** старт `Лестница A · 2 этаж`, назначение А-301 → 13 м через лестницу или 19 м через лифт.
3. **Доступный путь:** включить «Доступная среда» в форме или выбрать одноимённый вариант → лестницы исключаются из графа.
4. **Закрытый проход:** в настройках закрыть «Лестница между 2 и 3 этажами» → путь автоматически перестроится через лифт.
5. **Локальный QR:** открыть `/?node_id=stairs2` или отсканировать метку → старт меняется на лестницу второго этажа.

## QR-метки

Сканер принимает безопасный идентификатор точки из параметра `start_node` или `node_id`, проверяет его по графу и меняет старт маршрута. Внешняя ссылка из QR не открывается. Неизвестные идентификаторы показываются как ошибка и не влияют на текущий маршрут.

Печатные SVG/PNG-метки и два манифеста (`urls.json`, `locations.json`) создаются так:

```powershell
python -m pip install -r requirements.txt
python prepare_qr.py --base-url http://192.168.1.50:8080 --output qr
```

Адрес `192.168.1.50` приведён как пример. Телефон и компьютер должны видеть друг друга по сети. Для постоянной публикации нужен обычный HTTPS-хостинг.

## Замена демонстрационных данных

- `data/graph.json` — этажи, точки, проходы, длины и доступность;
- `data/timetable.demo.csv` — тестовое расписание, которое используется автоматически, пока реальных данных нет;
- `data/timetable.csv` — место для реального расписания. Сейчас в файле оставлена только строка заголовков. Как только в нём появится хотя бы одно занятие, сервер начнёт использовать этот файл вместо тестового.

Формат обоих CSV одинаков: `group_id,date,start,end,room_id,title`. Чтобы вернуться к тестовым данным, оставьте в `timetable.csv` только заголовок. Python- и Node-серверы перечитывают файлы при следующем API-запросе; после добавления новых групп обновите страницу, чтобы обновился список групп в форме.

Если непустой `timetable.csv` содержит ошибку, приложение сообщит о ней и не станет незаметно подменять реальные данные тестовыми.

После изменения данных выполните `python app.py --check`. Проверка подтверждает корректность ссылок, типов, координат и связность графа. Реальные длины и доступность маршрутов нужно подтвердить обходом корпуса.

Ребро можно штатно закрыть в `graph.json` флагом `"closed": true`. Поле `"accessible": false` исключает его только из маршрута «Доступная среда».

## API

- `GET /api/data` — валидированный граф, активное расписание и его источник (`schedule.source`);
- `GET /api/timetable?group_id=ИСП-21&at=2026-11-16T09:45` — текущая или следующая пара;
- `GET /api/health` — JSON с `status: "ok"`, версией графа и режимом `DEMO`/`Production`.

Все API-ответы отдаются с `Cache-Control: no-store, no-cache, must-revalidate`.

QR распознаёт локальная библиотека `jsQR 1.4.0` (Apache-2.0); её лицензия находится в `vendor/jsQR.LICENSE.txt`.
