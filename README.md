# Мультикампусный навигатор

Локальный веб-навигатор по учебным корпусам: выбирает ближайший кампус, показывает расписание по системному времени, строит маршрут между парами и ведёт пользователя внутри здания без GPS.

## Итоговый функционал

### Кампусы и города

- единый каталог `data/graph.json` хранит несколько независимых графов зданий;
- в демонстрационных данных есть главный корпус в Москве, технологический корпус в Казани и городские учебные корпуса в Астрахани, Воронеже, Екатеринбурге, Краснодаре, Красноярске, Нижнем Новгороде, Новочебоксарске, Сочи, Тюмени и Чебоксарах;
- городские корпуса собираются из общей схемы `city-campus`, поэтому их этажи и маршруты не дублируются в JSON;
- каждый кампус имеет город, название, часовой пояс, географические координаты, этажи, узлы и проходы;
- селектор в шапке позволяет вручную сменить город и корпус;
- при первом старте браузер может определить ближайший кампус по геопозиции;
- ручной выбор запоминается локально и не заменяется геолокацией при следующем запуске;
- параметр `campus_id` фиксирует кампус в ссылках и QR-кодах, поэтому одинаковые ID точек разных зданий не конфликтуют.

Геолокация применяется только для выбора города/корпуса. Перемещение внутри здания не использует GPS и не отправляет координаты на сервер.

### Расписание

- ручного поля даты и времени нет;
- интерфейс отображает системное время устройства, преобразованное в часовой пояс выбранного кампуса;
- расписание перечитывается из CSV без перезапуска Python-сервера;
- блок пары автоматически показывает состояние «Идёт сейчас» или «Следующая пара»;
- для текущей пары отображается также следующая: время, предмет и кабинет;
- кнопка «К следующей паре» строит путь из кабинета текущей пары в кабинет следующей;
- во время перемены началом становится кабинет последней завершённой пары этого дня;
- до первой пары маршрут начинается из текущей QR-точки/чекпоинта;
- при сбое запроса расписания его загруженная копия используется до следующей проверки данных корпуса. Если проверка корпуса завершается ошибкой, карта скрывает путь до восстановления данных.

### Маршруты

- алгоритм Дейкстры строит кратчайший путь по графу помещений;
- в списке «Куда» перечислены все помещения корпуса, а не только аудитории: коворкинг, библиотека, лаборатория, проектная, гардероб, санузлы и зоны отдыха; рядом с названием указан этаж;
- доступны обычный и безбарьерный варианты;
- маршрут учитывает постоянно и временно закрытые проходы;
- показываются этажи, расстояние, примерное время и пошаговые инструкции;
- переход между этажами выполняется через лестницы или лифты согласно выбранному режиму;
- ссылку на маршрут можно скопировать вместе с кампусом, группой, стартом и целью.

### Живая навигация без GPS

- текущая позиция показана направленной стрелкой на SVG-карте;
- `DeviceOrientationEvent` плавно поворачивает стрелку по компасу смартфона;
- `DeviceMotionEvent` распознаёт шаги и продвигает стрелку по рассчитанной полилинии маршрута;
- условная длина шага равна 0,75 м; это навигационная оценка, а не точное измерение;
- при межэтажном переходе активная схема переключается автоматически;
- остаток пути и подпись текущего положения обновляются в реальном времени;
- QR-скан или клик по пунктирному чекпоинту уточняет этаж и координату;
- у QR-узлов можно задать `heading` — направление контрольной точки на плане; при наличии данных компаса оно используется как поправка;
- кнопка «Сбросить поправку» возвращает стрелку к выбранному старту и убирает компасную коррекцию;
- при включённом `prefers-reduced-motion` анимации сокращаются средствами CSS.

Компасс и датчик движения обычно доступны только на HTTPS или `localhost` и требуют разрешения пользователя. Магнитные помехи внутри здания неизбежны, поэтому QR/checkpoint-калибровку следует повторять возле контрольных точек.

### QR

- видео и снимки обрабатываются локально библиотекой `vendor/jsQR.js`;
- наружу не отправляется изображение камеры;
- поддерживаются живой видеопоток, системная камера и готовый снимок;
- QR может содержать URL или JSON с `campus_id` и `start_node`/`node_id`;
- сканирование метки другого кампуса сначала переключает корпус, затем применяет точку;
- неизвестные кампусы и узлы не меняют действующий маршрут.

При открытии ссылки с неизвестной меткой старт остаётся пустым. При сканировании в приложении можно перейти к ручному выбору старта из сообщения об ошибке.

## Структура данных

Сокращённая схема `data/graph.json`:

```json
{
  "version": "singularity-2026-11-18-r4",
  "demo": true,
  "default_campus_id": "moscow-main",
  "templates": {
    "city-campus": {"floors": [], "nodes": [], "edges": []}
  },
  "campuses": [
    {
      "id": "moscow-main",
      "city": "Москва",
      "name": "Главный учебный корпус",
      "short_name": "Главный корпус",
      "timezone": "Europe/Moscow",
      "coordinates": {"latitude": 55.7558, "longitude": 37.6173},
      "floors": [],
      "nodes": [],
      "edges": []
    },
    {
      "id": "yekaterinburg-campus",
      "city": "Екатеринбург",
      "name": "Городской учебный корпус",
      "short_name": "Городской кампус",
      "timezone": "Asia/Yekaterinburg",
      "coordinates": {"latitude": 56.8389, "longitude": 60.6057},
      "template": "city-campus"
    }
  ]
}
```

Python- и Node-серверы разворачивают `template` в полный граф при загрузке, поэтому клиент всегда получает готовые `floors`, `nodes` и `edges`.

Узел с `"room": true` считается помещением-целью: он попадает в список «Куда» и может использоваться в расписании. Служебные помещения (коворкинг, библиотека, гардероб, санузлы, зоны отдыха) описаны такими же узлами с одним проходом к коридору или лифту.

Оба файла расписания используют формат:

```text
campus_id,group_id,date,start,end,room_id,title
```

- `data/timetable.csv` — реальные данные;
- `data/timetable.demo.csv` — демонстрационный резерв;
- выбор источника выполняется отдельно для каждого кампуса: если в реальном CSV есть строки корпуса, используются они, иначе — его демонстрационные строки;
- кабинет обязан существовать в графе соответствующего кампуса;
- занятия одной группы в один день не могут пересекаться.

Демонстрационное расписание задано на **18 ноября 2026 года**. Московские группы проходят по пяти парам на трёх этажах, казанские — по пяти парам на двух этажах. У каждого городского корпуса есть одна демо-группа с пятью парами; занятия заканчиваются в 17:10.

## Запуск

Python 3.11+:

```powershell
python app.py --check
python smoke.py
python app.py --host 0.0.0.0 --port 8080
```

Открыть на этом компьютере:

```text
http://127.0.0.1:8080/
```

Альтернативный сервер на Node.js 18+:

```powershell
node server.js --host 0.0.0.0 --port 8080
```

Телефон в той же сети может открыть LAN-адрес компьютера. На обычном HTTP LAN-адресе браузер часто блокирует непрерывную камеру, компас и датчик движения. Для полной мобильной навигации нужен HTTPS; системный снимок QR остаётся запасным вариантом.

### HTTPS для проверки с телефона

```powershell
python -m pip install cryptography
python make_cert.py
python app.py --host 0.0.0.0 --port 8443 --cert certs/server.crt --key certs/server.key
```

`make_cert.py` создаёт локальный удостоверяющий центр `certs/ca.crt` и подписанный им сертификат сервера `certs/server.crt` для `localhost` и всех IP-адресов компьютера. Сервер печатает готовые `NETWORK_URL` — откройте на телефоне `https://<LAN-IP>:8443/`.

Чтобы убрать предупреждение браузера, установите `certs/ca.crt` на телефон один раз; файл также отдаётся сервером по адресу `/ca.crt`:

- Android: «Настройки» → «Безопасность» → «Шифрование и учётные данные» → «Установить сертификат» → «Сертификат ЦС»;
- iOS: скачать профиль, затем «Настройки» → «Профиль загружен» → «Установить» и включить полное доверие в «Настройки» → «Основные» → «Об этом устройстве» → «Доверие сертификатам».

Без установки ЦС страницу можно открыть, приняв предупреждение, но камера, компас и датчик движения могут остаться заблокированными. Каталог `certs/` в `.gitignore`: приватные ключи не коммитятся. Повторный запуск `make_cert.py` переиспользует CA и выпускает новый сертификат сервера.

### Публичный адрес через туннель

Если телефон не в одной сети с компьютером, поднимите сервер на `127.0.0.1:8080` и запустите туннель:

```powershell
python app.py --host 127.0.0.1 --port 8080
.\tunnel.ps1
```

`tunnel.ps1` создаёт Cloudflare Quick Tunnel с валидным HTTPS-сертификатом, перезапускает его после обрыва сети и записывает актуальный адрес в `tunnel-url.txt`. Адрес случайный и меняется при каждом новом туннеле; постоянное имя возможно только в именованном туннеле с аккаунтом Cloudflare. Трафик идёт через сторонний релей, поэтому для реальных данных используйте локальный HTTPS.

## Редактор кампусов

В навигаторе откройте «Настройки» → «Редактор кампусов» или перейдите на `/editor`. Общий пароль по умолчанию — `dattebayo`. Задать другой пароль для Python- или Node-сервера можно через переменную среды `NAVIGATOR_EDITOR_PASSWORD` перед запуском.

1. Выберите существующий корпус или «Новый кампус». Для нового корпуса укажите название, город, ID, часовой пояс и координаты.
2. Выберите этаж и загрузите схему в PNG, JPEG или WebP. Клик по схеме ставит контрольную точку. В панели справа можно назвать точку, переместить её, назначить главным входом или отметить как место назначения.
3. Чтобы навигатор строил путь, соедините точки проходами и укажите их длину в метрах. Для перехода между этажами выберите лестницу или лифт. Контрольные точки можно опубликовать до добавления проходов.
4. Нажмите «Опубликовать» и откройте корпус в навигаторе. План и точки сохраняются в `data/graph.json` и становятся доступны всем посетителям. Для нового корпуса расписание можно добавить позднее через CSV.

Контрольные точки получают ссылки с ID кампуса и точки. Команда `prepare_qr.py` включает их в печатные QR-метки после публикации.

## API

- `GET /api/campuses` — версия, кампус по умолчанию и краткий каталог с координатами;
- `GET /api/data?campus_id=moscow-main` — граф и активное расписание одного кампуса;
- `GET /api/timetable?campus_id=moscow-main&group_id=ИСП-21&at=2026-11-18T09:45` — текущая, следующая и предыдущая пары, а также `route_from`/`route_to`;
- `GET /api/health?campus_id=moscow-main` — состояние, версия и источник расписания.

API и статические файлы отдаются с запретом кеширования, чтобы изменения CSV появлялись без устаревшей браузерной копии. Сами CSV и JSON напрямую через HTTP не публикуются.

## Печатные QR-метки

```powershell
python -m pip install -r requirements.txt
python prepare_qr.py --base-url https://navigator.example.org --output qr
```

Генератор создаёт отдельный каталог каждого кампуса:

```text
qr/
├── moscow-main/
│   ├── entrance.svg
│   └── entrance.png
├── kazan-tech/
│   ├── entrance.svg
│   └── entrance.png
├── urls.json
└── locations.json
```

Манифест содержит кампус, город, этаж, контрольное направление и пути к файлам.

## Публикация закрытого прохода

1. Скопируйте каталог `data` в `data-staging`. В копии `graph.json` найдите корпус по `campuses[].id`, затем проход по `edges[].id`. Если корпус использует общий шаблон, сделайте копию шаблона с новым ID и укажите его в поле `template` нужного корпуса. Меняйте проход в этой копии, чтобы закрытие затронуло только выбранный корпус.
2. Добавьте выбранному проходу `"closed": true` и обновите значение `version` в корне файла. Для открытия прохода используйте `"closed": false`.
3. Проверьте подготовленную версию командой `python app.py --data data-staging --check`. После успешной проверки замените файл на сервере. Если оба каталога на одном томе, из корня проекта можно выполнить:

   ```powershell
   [System.IO.File]::Replace(
       (Resolve-Path 'data-staging/graph.json').Path,
       (Resolve-Path 'data/graph.json').Path,
       (Join-Path (Resolve-Path 'data').Path 'graph.previous.json')
   )
   ```

4. В открытом навигаторе выберите «Настройки» → «Обновить данные» или дождитесь автоматической проверки. Она запускается каждые 10 секунд в видимой вкладке. Сверьте версию и проверьте, что маршрут обходит закрытие или показывает отсутствие пути. При ошибке данных в блоке маршрута доступна кнопка «Повторить загрузку».

Флажки в настройках позволяют проверить объезд в текущей вкладке. Опубликованные закрытия действуют для всех посетителей.

### Проверка на демонстрационных данных

В московском корпусе распечатайте сгенерированный QR для узла `entrance`. Откройте код камерой телефона и проверьте три цели на первом этаже: А-101, А-103 и А-105. Для А-101 закрытие `hall-lab1` должно переключить путь на обход через узел лифта на том же этаже. Закрытие `entrance-hall` должно убрать путь от входа. Для проверки неизвестного QR используйте ссылку на тот же сайт с `campus_id=moscow-main&start_node=unknown`. Проверьте, что при её открытии старт остаётся пустым и его можно выбрать вручную.

## Проверка

```powershell
python smoke.py
```

Smoke-набор выполняет:

1. полную валидацию графов и расписаний;
2. Python-тесты API, мультикампусности, горячей перезагрузки и QR-ссылок;
3. синтаксическую проверку клиентского и Node.js-кода;
4. HTTP-проверки Node.js-сервера на временном порту: каталог кампусов, изоляция данных, расписание, ошибки и приватность CSV;
5. JavaScript-тесты маршрутов, расписания, географического выбора и движения по маршруту.

Демонстрационные планы и длины проходов необходимо подтвердить физическим обходом перед эксплуатацией. Детектор шагов и компас являются вспомогательной навигацией, а не системой позиционирования для задач безопасности.

`jsQR 1.4.0` распространяется по Apache-2.0; лицензия находится в `vendor/jsQR.LICENSE.txt`.
